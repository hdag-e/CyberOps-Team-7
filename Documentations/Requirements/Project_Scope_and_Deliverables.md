# Project Scope and Deliverables (SCRUM-78)

## 1. Purpose

This document summarizes the approved scope and required deliverables for
CYBEROPS-07. It provides the team with a common reference for determining
what work is required and what work is outside the project scope.

## 2. Project Objective

The project will build and demonstrate a simulated Security Operations
capability using Cisco Packet Tracer. The team will generate security
events, classify and triage those events, manually correlate evidence,
reconstruct multi-stage incidents, and develop NIST-aligned incident
response playbooks.

## 3. In-Scope Work

The project includes:

- Enterprise network monitoring foundation
- Centralized security logging
- Network time synchronization
- Clock-skew demonstration
- Security event generation and documentation
- Event taxonomy and severity classification
- Triage procedures
- Escalation matrix
- Manual event correlation
- Multi-stage incident reconstruction
- NIST-aligned incident response playbooks
- MITRE ATT&CK technique mapping
- Monitoring coverage gap analysis
- Blind incident-response exercise
- Final documentation and presentation

## 4. Required Deliverables

| ID | Deliverable |
|---|---|
| D1 | Packet Tracer enterprise network |
| D2 | Monitoring/logging foundation |
| D3 | Security event catalogue |
| D4 | Event taxonomy and triage procedure |
| D5 | Manual correlation workbook |
| D6 | Multi-stage incident reconstructions |
| D7 | NIST-aligned incident response playbooks |
| D8 | Monitoring coverage gap assessment |
| D9 | Blind exercise and validation evidence |
| D10 | Final report, presentation, and video |

## 5. Out-of-Scope Work

The following are outside the project scope:

- SIEM implementation
- IDS deployment
- Commercial security tooling
- Host-based analysis
- Packet capture beyond Packet Tracer capabilities
- Infrastructure development as the primary project activity
- Layer 2 attack execution or hardening
- Firewall/perimeter design
- Identity-system development
- Threat intelligence integration
- Compliance implementation
- Physical hardware deployment
- Ongoing production operations

## 6. Scope Control

New work should be evaluated against the approved project scope before
being added to the backlog. Work that does not directly support the
project objective or required deliverables should be discussed by the
team before being accepted.

## 7. Review

The project scope and deliverables will be reviewed throughout the
project to ensure that sprint work remains aligned with the approved
requirements.
