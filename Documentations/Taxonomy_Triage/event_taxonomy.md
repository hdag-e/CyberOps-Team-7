## Analytical Questions and Response Categories

|---|---|---|---|
| [EVT-01](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/EVT01_State_Flap) | Was this interface state change preceded by an approved maintenance ticket or triggered by an unexpected physical layer disruption? | Correlate |Compare interface change with maintenance records and connectivity records to distinguish if the change was authorized or a disruption |
| [EVT-02](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/EVT02_global_config) | Does this configuration modification align with an approved change request ticket, or was it executed outside of standard maintenance windows? | Log only |The loge message does not identify why the changes where done so it could move to correlate but on its own it is only log  |
| [EVT-03](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/EVT03_Authentication_Failure) | Is this failed login an isolated administrative typo or part of an active brute-force campaign against network infrastructure? | Correlate | a single failure may just be a type or legitimate mistake more attempt frequency could establish malicious intent |
| [EVT-04](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/EVT04_ACL_deny) | Is this packet filtering drop indicative of routine network noise or a targeted reconnaissance probe against the network perimeter? | Correlate |Blocking activity does not establish if that activity was malicious or not so traffic sources need to be compared along with frequency |
| [EVT-05](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/EVT05_device_reload) | Was this system restart executed during an approved outage window or did an unexpected fault or unauthorized trigger cause the reload? | Immediate action | The reason for the reload needs to be established as if it was outside of maintenance it could cause major disruptions to the network |
| [EVT-06](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/scrum168_event_records%20%281%29.md) | Was this interface state change pre-approved by an active network change ticket? | Correlate | Needs more information on why the state went down and if it was part of maintenance. Compare configuration records as well as the network plan|
| [EVT-07](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/scrum168_event_records%20%281%29.md) | Do the newly added configuration parameters (VLAN 999) match an approved architecture ticket? | Correlate |needs more information if the VLAN was approved to be created or if it was created independently. compare VLAN creation with the network VLAN plan |
| [EVT-08](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/scrum168_event_records%20%281%29.md) | Did this login failure originate from an authorized console/management station, and was it followed by account lockout? | Correlate / Monitor |an initial failed login does not establish any malicious activity. the source and frequency needs to be determined to see if it is legitimate |
| [EVT-09](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/scrum168_event_records%20%281%29.md) | Is MAC address 0030.A314.C145 listed in the corporate asset management inventory? | Immediate action |Needs to be determined if this was part of maintenance or if this is unauthorized as a rogue connection to the port could cause major disruptions |
| [EVT-10](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/scrum168_event_records%20%281%29.md) | Was an unauthorized switch or bridge device physically attached to access interface FastEthernet0/11? | Immediate action |Needs to be determined if this was accidental or on purpose and if it was authorized |
| [EVT-11](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/event_evt11_native_vlan_mismatch_20261030.md) | Was the native-VLAN mismatch authorized as part of testing, or caused by an unintended change? | Correlate / Monitor |  Trunk ports need to be compared with the approved design as the warning does not prove intent or impact|

| [EVT-13](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/event_evt_13_duplicate_ip_detection_20261031.md) | Which endpoint claimed 192.0.2.1, was the assignment authorized, and did the conflict affect connectivity? | Correlate | Identify the mac address and compare that with the network addressing plan to distinguish if it was accidental or unauthorized address use|
| [EVT-14](https://github.com/hdag-e/CyberOps-Team-7/blob/main/Evidence/Sprint_3/Event_Catalogue/event_evt14_root_guard_blocking_20261101.md) | Was the superior BPDU caused by an authorized topology change, a configuration mistake, or an unauthorized attempt to influence root election? | Correlate |The message does not establish an attack, compare neighbor identity, bridge priority and approved changes |
